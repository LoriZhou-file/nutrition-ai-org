# 第一期用户端雏形

手机端网页：同意 → 排除筛查 → 基本情况 → 血糖与用药 → 一天饮食 → AI 追问 → 饮食小结 → 档案确认 → 陪跑意向。
后端是 FastAPI，规则引擎和输出校验在模型之前、之后各执行一次。**这是雏形，用来给大家看、试、提意见，不能对外使用。**

## 运行

```bash
pip install -r prototype/requirements.txt
cp prototype/.env.example prototype/.env     # 填 DEEPSEEK_API_KEY；不填则自动进入演示模式
python -m uvicorn prototype.server:app --port 8000
```

浏览器打开 http://localhost:8000 （手机尺寸效果更好，可在浏览器里切换成手机视图）。

- 页面右上角会显示当前引擎：`演示模式（未接入大模型）` 或 `模型：deepseek-chat`。
- 用真实模型试跑一次并检查能否通过安全校验：`python -m prototype.check_llm` 或 `python -m prototype.check_llm conservative`。
- 换模型：改 `LLM_BASE_URL`、`LLM_MODEL`，不用改代码（需兼容 OpenAI 接口）。

## 测试

```bash
python -m pytest prototype/tests -q
```

覆盖：安全规则（对应 `evals/safety/`）、输出硬性检查（对应 `evals/diet_advice/`）、保守模式、排除筛查、同意与档案结构校验、完整流程。

## 已经做了什么

| 能力 | 说明 |
|---|---|
| 排除筛查 | 未满 18 岁、孕期哺乳期、1 型糖尿病、严重肾病或进食障碍 → 直接转介，不进入饮食环节 |
| 保守模式 | 只要用药或不确定是否用药，就走保守规则（见下方决策点） |
| 规则前置 | 胸痛、疑似低血糖、疑似高血糖急症、进食障碍 → 终止建议并给固定话术；要求调药、极端节食、要求诊断 → 提示并回避该话题 |
| AI 追问 | 缺少份量、做法、饮料含糖情况时先追问，最多 3 个 |
| 建议输出 | 最值得先改的 3 点，针对用户实际吃的东西，只用份量单位 |
| 输出校验 | 禁用词、自称身份、药量、克数与热量、保守模式下的危险建议、必要提示；不通过则重试一次，仍不通过用预置的安全内容 |
| 知识检索 | 读取 `knowledge/*/extracted`，在页面显示依据的知识编号和“待审核”状态 |
| 档案 | 符合 `schemas/user_profile.schema.json`，不含姓名与手机号，可删除 |

## 还没有做、或者是演示用的

- **关键词是演示用的**（`demo_keywords.yaml`），阈值与关键词必须由营养师和医疗顾问审定。上线前替换。
- **知识单元全部是待审核**，页面上会标注。
- 指标数值异常（R-VALUE）等需要阈值的规则**没有实现**，因为阈值待审定。
- 没有拍照识别、没有营养师端、没有登录与支付、没有小程序封装。
- 演示模式的建议是用规则拼出来的，**不代表真实模型的水平**。真实效果要用 DeepSeek 跑，并用 `evals/` 里的用例评分。
- 真实模型这一路我没有在自己的环境里跑过（没有密钥），请你本机用 `check_llm` 先试一次。

## 需要营养师或医疗顾问拍板的点

1. 保守模式的触发范围：目前是“用任何降糖药或不确定”都走保守，比“仅胰岛素或促泌类”更保守，因为用户通常分不清药的类型。
2. 低血糖关键词和触发条件（R-HYPO）。
3. 哪些饮食建议在保守模式下可以说、哪些不能说。
4. 排除人群的划线。
