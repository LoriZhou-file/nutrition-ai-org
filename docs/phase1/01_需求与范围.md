# SeekNutri 第一期（Phase 1）需求与范围

> 状态：草案 v0.1，待项目负责人与营养师顾问团评审。
> 本文件只新增，不修改 `agents/`、`configs/` 与已有知识单元。

## 1. 第一期一句话目标

视频 → 免费控糖 AI 工具 → 结构化档案 → 个人控糖自查小结。
只做用户端，不涉及任何产品销售和付费服务。

第一期要验证三件事：

1. 视频流量愿意进入工具并完成档案（入口有效）。
2. AI 对"一天饮食"给出的建议，真人营养师认为有价值且安全（质量有效）。
3. 用户对"营养师陪跑"有多大意愿（需求信号，只收意向，不定价、不收款）。

## 2. 明确不做（第一期）

- 不做任何产品或服务的销售，不做成品库、支付、分账。
- 不做营养师端工作台与专业 AI 助手。
- 不做拍照识别饮食（见第 6 节，第二期评估）。
- 不做医疗诊断、不涉及药物剂量与调整。
- 不做多平台直接打通，先统一用微信内入口。

## 3. 目标人群与排除规则

目标人群：血糖偏高的成年人，包括已使用降糖药物或胰岛素者。核心价值是药物之外的生活习惯调整，尤其是饮食结构。

| 类别 | 处理方式 |
|---|---|
| 一般人群（未用药，血糖偏高或关注血糖） | 标准模式 |
| 使用胰岛素或促泌类降糖药 | **保守模式**（见 `02_对话流程与话术规则.md` 第 4 节） |
| 1 型糖尿病 | 不提供饮食方案，转介医生或营养师 |
| 孕期或哺乳期 | 不提供饮食方案，转介 |
| 未满 18 岁 | 不提供服务 |
| 严重肾病、进食障碍史 | 不提供饮食方案，转介 |

> 上表的最终划线由真人营养师与医疗顾问审定。

## 4. 用户旅程

1. 看到视频 → 通过口令或二维码进入微信小程序。
2. 阅读并同意隐私说明与单独同意（健康信息）。
3. 排除筛查（几个必答的安全问题）。
4. 基础信息与血糖、用药情况。
5. 逐餐填写一天饮食，AI 追问份量与做法。
6. 风险规则判定（绿 / 黄 / 红）。
7. 输出个人控糖自查小结（最多 3 个优先改善点，针对其实际饮食）。
8. 用户查看、修改并确认结构化档案。
9. 可选：留下"想了解营养师陪跑"的意向。不收费，不承诺服务。

## 5. 入口与技术路线

| 项 | 决定 | 说明 |
|---|---|---|
| 主入口 | 微信小程序 | 可搜索、可分享 |
| 兜底入口 | H5 | 同一后端，第二个前端 |
| 服务号 | 第二期 | 用于留存与触达 |
| AI 编排 | Dify，部署在境内服务器 | 沿用现有经验，数据留在境内 |
| 大模型 | DeepSeek，经抽象层接入 | 保留切换能力 |
| 知识 | 检索增强，仅使用"已审核"知识单元 | 未审核资料不进入对外回答 |
| 风险 | 规则引擎前置拦截（代码实现） | 不依赖模型自由判断 |
| 数据 | 存储与模型调用在境内，最小化采集 | 第一期不收姓名、手机号 |

## 6. 已知限制与后续评估

- DeepSeek 官方接口主要是文本模型。拍照识别需另接视觉模型，且份量难以判断，放第二期评估。
- 第一期用文字逐餐填写，由 AI 追问份量与烹饪方式。

## 7. 第一期成功指标（目标值待基线数据后填写）

| 指标 | 含义 | 目标值 |
|---|---|---|
| 进入率 | 视频观看到进入工具 | 待基线 |
| 档案完成率 | 开始到完成确认 | 待基线 |
| 饮食建议完成率 | 提交一天饮食并看到建议 | 待基线 |
| "有帮助"评价 | 用户对建议的反馈 | 待基线 |
| 意向留资率 | 点击"想了解陪跑" | 待基线 |
| 风险分布 | 绿 / 黄 / 红占比 | 仅观察 |
| 营养师评测通过率 | 见 `evals/diet_advice/` | 营养师顾问团定 |

## 8. 角色分工（第一期）

| 角色 | 本期职责 |
|---|---|
| 项目负责人（真人） | 决策、主体与备案、对外合作 |
| 项目经理 Bot | 任务台账、依赖与风险跟踪 |
| 产品 Bot | 本文件、对话流程、档案字段 |
| 系统架构 Bot | Dify 工作流、规则引擎、数据结构、备案与部署方案 |
| 营养师 Bot | 知识整理、评测用例初稿、规则初稿 |
| 文案策划 Bot | 视频下方引导语、小程序文案（合规用语） |
| 营养师顾问团（真人） | 审核知识、审定风险规则、评测打分、讨论陪跑方案 |

暂停：供应链 Bot（第一期不涉及产品）。

## 9. 里程碑（估算，待系统架构 Bot 与外包方核实）

约 4–6 周。关键路径是备案、营养师审核、评测通过，而不是开发。

1. 第 0–1 周：共识、启动备案（网站与小程序）、搭建境内 Dify。
2. 第 1–3 周：对话流程、规则初稿、知识补充与审核、评测用例。
3. 第 3–5 周：小程序与后端联调、规则引擎、评测回归。
4. 第 5–6 周：营养师验收、小范围内测。
