# SeekNutri 第一期：AI 控糖入口设计说明

版本：v0.3（雏形阶段）　状态：待营养师审核，不对外使用

---

## 1. 一句话定位

**视频下方的“7 天控糖小挑战”：每天一个小任务，点一下打卡，第 7 天出小结，愿意的人再引导到营养师陪跑。**

第一期只做用户端，不涉及任何产品、服务和收款。

## 2. 要解决什么问题

| 问题 | 我们的做法 |
|---|---|
| 控糖视频有热度，但观众看完就走，没有留存 | 视频下方放入口，把观众变成有记录的用户 |
| 通用大模型也能聊控糖，我们没有优势 | 不做聊天，做“每天打卡”的习惯产品 |
| 用户没有“自己想问的问题” | 不让用户提问，由我们每天给一个具体任务 |
| 营养师需要了解用户 | 打卡记录本身就是档案：做没做到、卡在哪、选了什么 |

## 3. 目标用户

- 血糖偏高的人，包括正在用口服药或胰岛素的人。
- 核心价值：**药物之外，怎么把生活习惯调整对**（饮食结构、进食顺序、规律）。
- 不做：调药、诊断、治疗建议。

**不适合参加（会被转介，不给任何建议）**：未满 18 岁、孕期或哺乳期、1 型糖尿病、严重肾病或进食障碍。

## 4. 用户路径

```
视频 → 入口链接 → 开场页 → 30 秒安全确认 → 第 1 天任务
     → 每天打卡（1 分钟）→ 第 7 天小结 → 可选：留下“想了解营养师陪跑”的意向
```

### 4.1 开场页
一句话说明：每天一件小事，不节食，不记数字。说明“我是 AI 助手，不是医生”。

### 4.2 安全确认（只做一次）
- 勾选同意提供健康信息（不要姓名、手机号，可随时删除）。
- 4 个是/否：是否成年、孕期哺乳期、1 型糖尿病、严重肾病或进食障碍。
- 1 个选择：是否在用降糖药（没有 / 口服药 / 胰岛素 / 口服药和胰岛素 / 不确定）。

### 4.3 每日打卡
- 任务卡：今天做什么 / 为什么 / 怎么做。
- 三个按钮：**做到了 / 做了一部分 / 没做到**。
- 点完再点一个选项（可跳过）：
  - 做到了或做了一部分：回答一个与当天任务相关的小问题，如“哪一餐先吃的蔬菜”。
  - 没做到：选原因（忘了、没时间、在外吃、不喜欢、身体不舒服、其他）。
- 得到一句简短反馈，之后显示“明天见”。
- 可选：补充一句话（比如哪里不舒服）。
- 不支持跳过未来的天数；可以回看已解锁的天。

### 4.4 第 7 天小结
内容包括：做到、部分、没做到各几天；最顺手的任务；最常遇到的阻碍；想继续坚持的一件事。
下面是邀请：勾选“想了解营养师带着我继续做”，可写一句期望。**只记录意向，不收费、不绑定购买。**

## 5. 7 天任务内容（草稿，待营养师审核）

| 天 | 任务 | 性质 |
|---|---|---|
| 1 | 先看看，不用改：留意今天吃了什么 | 觉察 |
| 2 | 先吃蔬菜 | 进食顺序 |
| 3 | 饮料换一换 | 替换 |
| 4 | 主食搭配一下 | 搭配 |
| 5 | 早餐加一份蛋白质 | 增加，不是减少 |
| 6 | 吃饭尽量定时 | 规律 |
| 7 | 复盘，选一件坚持 | 巩固 |

**设计原则**：全部是“换、排序、规律、增加”，**没有任何“少吃、不吃、节食”类建议**。用药人群在相应任务下多一条提醒：不自行调整药物，吃药和进食安排听医生的。

内容文件：`knowledge/challenges/7day_glycemic.yaml`

## 6. 安全设计（从强到弱）

1. **准入筛查**：不符合条件的人直接转介，不进入挑战。
2. **风险规则先于模型**：用户写的备注先过规则；出现红级信号（如心慌手抖冷汗、胸痛喘不上气），**立即暂停挑战**，提示联系医生，且不再给饮食任务。
3. **保守模式**：只要在用药、不确定、或提到药物，就走保守模式（胰岛素人群已确认这样处理）。模型不能自己判断用药情况。
4. **输出校验在模型之后**：拦截疗效承诺（根治、保证降糖）、身份冒充（我是医生）、药量、具体克数和热量、保守模式下的不当建议。
5. **以模板为主**：每天的任务和反馈都是固定模板；只有用户写了备注，才会让 DeepSeek 回应一句，且必须通过校验，否则不显示。
6. **数据**：不收姓名手机号；用户可一键删除全部数据。

## 7. 数据：打卡记录即档案

每次打卡保存：第几天、日期、完成状态、没做到的原因、选的答案、备注（可选）。
这就是给营养师看的结构化档案：用户**愿意做什么、卡在哪里、对哪类任务有反应**，比一次性问卷更真实。
结构定义：`schemas/user_profile.schema.json`

## 8. 技术方案

- 前端：手机网页（H5），可放在视频链接下方；后续可包成小程序或服务号。
- 后端：FastAPI；模型使用 DeepSeek（OpenAI 兼容接口）；没有密钥时自动用演示模式。
- 服务器放中国境内。
- 本地运行：
  ```
  git fetch origin
  git checkout phase1-challenge
  pip install -r prototype\requirements.txt
  python -m uvicorn prototype.server:app --port 8000
  ```
  打开 `http://localhost:8000/?demo=1`，页面底部有“模拟到下一天”。
- 保留对照版：`/chat`（对话版）、`/form`（问卷版）。

## 9. 为什么不做聊天

- 用户自己说“没有我想问的问题”，也不想一直被追问“怎么吃”。
- 通用大模型在语音、图片、速度上都更强，我们无法在这里竞争。
- 我们的差异：**结构化、每天一个动作、有连续记录、能引到真人营养师**。

## 10. 当前局限

| 局限 | 说明 |
|---|---|
| 内容未经审核 | 任务、话术、风险关键词和阈值都需要营养师和医生审核 |
| 知识库很小 | 目前只有 12 条，缺水果等主题 |
| 无语音和图片 | DeepSeek 只处理文字；图片需另接视觉模型 |
| 无账号 | 同一浏览器能接着打卡，换设备不行 |
| 备案未完成 | 域名备案是上线的关键路径 |
| DeepSeek 真实输出 | 只有你本地验证过，需要用 `python -m prototype.check_llm` 评估 |
